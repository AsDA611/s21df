# 2026-09-30

## What was built

Workspace created from scratch in an empty directory, modeled on three sources and adapted rather than
copied: openclaw-prompts-and-skills (persona + bootstrap), ciembor/agent-rules-books (craft rules),
VoltAgent/awesome-openclaw-skills (catalog reference only — nothing installed).

Ten files plus nine skill modules. Nine commits, all English, working tree clean at each step.

## Decisions made

- **Skills are on-demand, never always-on.** Nine modules cost 2.2k chars resident (descriptions only)
  instead of ~12k. Progressive disclosure is what keeps the pack inside the 60k bootstrap budget.
- **One canonical rule set, thin adapters.** Per-tool files point at `AGENTS.md`; no rules are copied,
  because the stale copy is the one the agent obeys. Copilot and OpenHands got symlinks for the same
  reason — both load a fixed path and follow no pointer syntax.
- **Autonomy is risk-based, by the user's explicit choice.** I first refused a blanket "never refuse"
  requirement and kept consent gates for everything. The user overruled that and chose risk-based
  autonomy: local destructive work runs unasked, anything leaving the machine or spending money asks
  first. Five ambiguous cases were then identified and encoded explicitly in `AGENTS.md` §Autonomy.
- **No third-party skills installed.** The ClawHub catalog is curated, not audited. The vetting rules
  live in `AGENTS.md` §Untrusted content; the separate `SKILLS.md` index was later deleted as inert.
- **Inert indexes deleted.** `BOOKS.md` and `SKILLS.md` were both never-resident lookup tables. Removed;
  the useful commands remain in the README's Budget section.

## Gotchas found

- Copilot reads *only* `.github/copilot-instructions.md`. A text file telling it to read `AGENTS.md` is
  worse than useless — the rules were dormant until it became a symlink. Aider is the same until
  `read:` is configured.
- Hermes reads `<project-root>/.agents/skills/` natively, so it needed no adapter, but it refuses to load
  project skills from an untrusted clone: `hermes skills trust` first, or the nine modules stay invisible.
- Hermes house style caps a skill description at 60 characters. Ours are 215–265 because trigger matching
  is what makes them fire elsewhere. Deliberate conflict, documented.

## Verified

- 9/9 skill frontmatter valid, every `name:` matches its directory, index has no orphans.
- 10/10 tool entry points resolve.
- Always-injected layer 15.5k of 60k chars; largest file 7.1k against a 12k per-file cap.
- All 14 flagged cross-references were false positives (pointer syntax, date templates, prose examples).

## Trimmed

- Deleted as not needed, at the user's direction: `IDENTITY.md`, `USER.md`, `TOOLS.md`, `BOOTSTRAP.md`,
  `session-close.sh`, two inert indexes, and twelve tool adapters (hooks, rule pointers, Aider and Claude
  configs). What remains: `SOUL.md`, `AGENTS.md`, nine skills, `MEMORY.md`, this log.
- The cost, stated plainly: the 12k per-file cap now drops the tail of `AGENTS.md` silently with nothing
  watching for it, and session close is manual with no enforcement.
